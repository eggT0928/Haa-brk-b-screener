# 수진 포트폴리오 통합 — 공유 자동 갱신 / 수동 보조

작업 브랜치: `feat/couple-rebalancer`. 2026-08-30 구현·로컬 검증 후 사용자 승인으로 **기존 전용 Firebase 프로젝트에 운영 배포 완료**했습니다. main은 머지하지 않았습니다.

운영 주소: <https://haa-portfolio-260830.web.app/>. 공유 자동 작업 수동 실행으로 현근·수진 시세 동시 저장을 확인했고, 수진 수동 갱신 및 실제 백테스트도 성공했습니다. 실제 보유수량·계산안 저장은 대신 실행하지 않았습니다.

## 적용 범위

- 상단에서 `남편 · 현근` / `아내 · 수진`을 선택합니다. 탭을 오가도 저장하지 않은 입력은 유지됩니다. 새로고침 전에는 각자 저장 버튼을 눌러야 합니다.
- 두 포트폴리오를 관리합니다. 후속 `feat/family-access`에서 아내의 별도 Google 계정도 이메일 초대·승인 후 동일 데이터를 공유하도록 추가했습니다. [가족 권한 안내](FAMILY_ACCESS.md)를 참고하세요.
- HAA 전략·SPY 기준 신호·장기 백테스트·기존 DBC 프록시·^IRX 및 현근의 기존 저장 경로는 그대로입니다.
- 원본 `eggT0928/sujin_portfolio`의 `d80e55db32fd109c2607f6e5e0112180e80dd641` 코드를 검토해 순수 계산을 이식했습니다. 원본 Streamlit 저장소와 별도 부부 투자 기록 앱은 변경하지 않았습니다.

## 수진의 계산 규칙

| 자산군 | 목표 비중 |
|---|---:|
| QQQM | 15% |
| SPY + SPYM | 20% |
| JEPQ | 10% |
| BRK-B | 15% |
| IEF | 15% |
| TLT | 10% |
| GLD | 10% |
| PDBC | 5% |

기존 SPY 수량은 그대로 유지하고 합산 20%에서 남은 금액을 SPYM으로 채웁니다. SPY만으로 이미 20%를 초과하면 목표 비중을 맞출 수 없으므로 매매 계산을 중단합니다. 원본에서 발생할 수 있던 음수 SPYM 목표·보유량 이상의 매도 계산을 차단합니다.

기본값은 원본처럼 총자산 직접 입력입니다. 최초 수량·금액은 모두 0이며 기존 Streamlit의 실계좌 수량을 자동 복사하지 않습니다. `보유주식 평가액 + 현금` 모드도 선택할 수 있습니다. 직접 입력 총자산에는 예수금·추가 투입금까지 포함해야 하며, 보유주식 평가액보다 작은 총액은 거부합니다.

신규 목표 수량은 기본 0.01주, 선택 시 1주 단위로 **내림**합니다. 이는 원본의 제한 없는 소수점 계산을 주문 단위에 맞춘 변경입니다. SPY는 기존 소수점 보유량도 그대로 유지합니다. 다른 종목은 기존 소수점 잔량을 매도하는 계산이 발생할 수 있습니다. 수수료·세금·실제 체결가격은 제외하며 증권사 주문을 실행하지 않습니다.

계산안 저장은 실제 매매 기록이나 자동 보유수량 변경이 아닙니다. 시세가 오래되었거나 갱신 실패 상태이면 확인 체크 후에만 저장할 수 있습니다. 계산 당시 총자산, 수량, 가격, 가격 기준시각을 수진 이력에 추가하며 수정·삭제는 허용하지 않습니다. 전체 계산표는 한국어 CSV로 내려받을 수 있습니다.

## 갱신과 비용 억제

기존 `refresh_intraday`, `refresh_daily` 두 함수와 일정만 사용합니다. **Scheduler 작업이나 배포 함수 수는 늘리지 않습니다.**

1. 기존 HAA 갱신을 먼저 검증·저장합니다.
2. 성공한 경우 `market/current`의 유효한 공통 6종목 가격·시각을 재사용합니다.
3. 보통 QQQM·JEPQ·GLD 3종목만 추가 조회해 `market/sujin`을 갱신합니다. 공통 시세가 누락·지연된 수동 요청에서는 필요한 종목을 추가 조회합니다.
4. 수진 전용 조회가 실패해도 이미 성공한 HAA 신호를 되돌리거나 HAA 작업 전체를 실패 처리하지 않습니다. 수진은 직전 성공값·기준시각을 유지하고 별도 실패 안내를 표시합니다.

HAA 자체가 실패·중복 실행·휴장일로 종료하면 해당 회차의 수진 자동 갱신도 실행하지 않습니다. 수진 실패는 다음 정상 자동 실행이나 수동 버튼으로 재시도합니다. 월말 확정 신호는 HAA만 있으며, 수진은 고정비중이므로 시세와 수량 계산안을 표시합니다.

수동 버튼은 인증·관리자 승인된 POST `/api/sujin/refresh`입니다. 페이지 방문이나 탭 전환만으로 Yahoo를 호출하지 않습니다.

- 장중 최근 10분 성공 캐시 재사용. 각 가격 자체도 25분 이내인지 확인합니다.
- 장외에는 마지막 거래일 종가가 맞으면 동일 종가를 재사용합니다. 주말에 조회 시각만 바꿔 실시간 가격처럼 보이게 하지 않습니다.
- Yahoo 조회 최대 2회, 요청별 시간 제한. 동일 종류의 재시도는 실패 후에도 최소 60초 간격이며 Firestore 트랜잭션 잠금은 2분입니다.
- 캐시가 없는 첫 요청이 실패하면 오류·대기를 표시하고 샘플을 실제 값으로 저장하지 않습니다.
- 수진 백테스트 이력은 실행 버튼을 누를 때만 조회하고 같은 완료 월 기준 12시간 재사용합니다. 자동 갱신 때마다 장기 이력을 별도로 받지 않습니다.

새 Scheduler 고정비는 없지만 추가 Yahoo 조회에 따른 Functions 실행시간, Firestore 읽기·쓰기, 네트워크 등은 증가할 수 있습니다. 무료 범위나 월 요금 0원을 보장하지 않습니다. 기존 최소 인스턴스 0·최대 1 설정을 유지합니다.

## 수진 장기 백테스트

원본처럼 SPY 10% + SPYM 10%, PDBC 자체, 월별 고정비중 재조정을 사용합니다. 현근 HAA의 SPY 단일 기준·DBC 프록시와 혼합하지 않습니다. 실전의 기존 SPY 수량 고정·주문 단위 내림은 이론적 백테스트에 적용하지 않습니다.

- 전체 ETF의 공통 이력이 있는 완료 월말부터 시작하며 기간·초기 금액을 선택할 수 있습니다.
- 실제 마지막 NYSE 거래일의 수정주가만 월말 가격으로 사용합니다. 미완료 현재 월은 제외합니다.
- 누락 자산을 빼고 나머지 비중을 재배분하거나 누락 월 수익률을 0%로 대입하지 않습니다.
- 초기 원금도 최대 낙폭의 최고값에 포함합니다.
- 선택 기간 일별 ^IRX 평균을 사용합니다. 조회 실패 시 기존 성공 캐시를 유지하며 임의 2.5%로 대신하지 않습니다.
- 기존 반응형 그래프·월별 툴팁·기간별 수익률 표를 재사용합니다.

## 데이터와 접근 권한

| 경로 | 용도 |
|---|---|
| `users/{uid}` / `users/{uid}/rebalances/*` | 기존 현근 데이터, 변경·이관 없음 |
| `users/{uid}/portfolios/sujin` | 수진 보유수량·총자산 모드·수량 단위·기간 |
| `users/{uid}/portfolios/sujin/rebalances/*` | 수진 계산안 이력, 최근 24건 표시 |
| `market/sujin` / `status/sujinQuotes` | 공용 수진 시세와 갱신 상태 |
| `internal/sujinHistory` / `status/sujinHistory` | 압축 월말 가격·일별 IRX 및 조회 상태 |
| `internal/sujinQuotesLease` / `internal/sujinHistoryLease` | 자동·수동 중복 방지 및 재시도 제한 |

포트폴리오 문서는 서버가 같은 ownerUid로 승인한 공유 구성원만 접근합니다. 위 표의 uid는 저장 공간 소유자의 UID이며 각 로그인 계정의 UID와 다를 수 있습니다. 공용 시세는 승인 사용자 읽기만, 내부 캐시·잠금은 서버만 접근합니다. 계산안은 필요한 5개 행 필드(종목·보유·목표·매매수량·가격)만 저장하고 9개 행 모두 검증하여 [규칙 평가 한도](https://firebase.google.com/docs/rules/rules-behavior) 안에서 처리합니다. 초대·권한 관리는 [후속 가족 기능](FAMILY_ACCESS.md)의 서버 API만 담당합니다.

## 검증 및 배포 순서

자세한 실제 결과는 [검증 기록](VALIDATION.md)의 수진 통합 항목을 확인하세요. GitHub Actions는 테스트·빌드·권한 검증만 실행하며 배포하지 않습니다.

최초 통합 배포는 사용자 승인 후 완료했습니다. 향후 재배포도 별도 승인을 받은 뒤 기존 전용 프로젝트에 다음을 배포합니다. 신규 Firebase 프로젝트·결제 연결·환경변수는 필요하지 않습니다. `VITE_DEMO_MODE=false`, `VITE_USE_EMULATORS=false`를 확인해야 합니다.

```bash
npm test
pytest -q
npm run test:rules
npm run build
# 아래 명령만 실제 운영 변경: 반드시 별도 승인 후 실행
npx firebase deploy --only firestore:rules,functions,hosting --project haa-portfolio-260830
```

배포 후 확인 사항:

- 로그인과 기존 현근 보유수량·신호·백테스트가 그대로인지 확인.
- 수진 탭 및 수동 갱신으로 `market/sujin` 첫 성공값 확인. 첫 성공 전에는 대기·오류가 정상이며 가짜 시세로 채우지 않음.
- 사용자가 실제 수진 수량을 입력·저장하고 새로고침 후 복원 확인. 테스트용 임의 수량을 운영에 대신 입력하지 않음.
- 다음 미국 장중 실행에서 기존 두 예약 작업만으로 양쪽 시세가 갱신되는지 확인.
- 수진 백테스트 실제 클라우드 경로·계산안 저장을 사용자 입력으로 확인.
- 이상 시 Hosting만 이전 릴리스로 되돌릴 수 있으나, 전체 취소는 Functions·규칙도 기존 검증 버전으로 재배포해야 함. 개인 문서 삭제·기존 데이터 이관은 필요하지 않음.

main 머지는 운영 배포와 별도로 사용자 확인 후 진행합니다.
